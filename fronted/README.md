# Easy Community 前端

React + TypeScript + Vite，使用原生 CSS 与 React Router。目录名称沿用仓库中的 `fronted`。

## 启动与构建

建议使用 Node.js 24 LTS 和 npm。本次验证环境为 Node.js 24.18.0、npm 11.16.0；依赖版本以 `package-lock.json` 为准。

```powershell
cd fronted
npm ci
npm run dev
```

浏览器访问 `http://127.0.0.1:5173`。开发服务器与构建预览显式监听 IPv4，避免 localhost 解析到 IPv6 时连接失败。Vite 将相对 `/api` 请求转发到 `http://127.0.0.1:8080`，保留 Host、路径前缀和 Cookie。开发时统一使用 127.0.0.1，避免与 localhost 混用导致 Cookie 隔离。

```powershell
npm run typecheck
npm test
npx playwright install chromium
npm run test:e2e
npm run build
```

浏览器测试在 5175 端口自动启动生产构建预览，不占用 5173。测试接口仅在 Playwright 浏览器内拦截，不依赖后端；失败保留截图和 trace，布局截图位于 `test-results/`。页面没有生产环境的假数据或模拟登录开关。

构建结果位于 `dist/`。部署时由静态服务器承载，前端路由回退 `index.html`，并在同一 Origin 下转发 `/api/` 到后端，可参考仓库 `backend/examples/nginx.conf.template`。`vite preview` 只用于本地验收。

## 已实现边界

- `/`：主页三栏、顶部与侧栏吸顶、静态横幅、推荐流连续加载。最小宽度 1440px，窄屏横向滚动，背景固定覆盖视口。
- `/login`：账号密码登录、必填反馈、密码显隐、CSRF、提交锁、限流倒计时与登录后返回首页。小于 1024px 时优先显示表单，短窗口允许纵向滚动。
- `/manage/articles`：本人公开文章、内部滚动、游标续页、保留旧内容的刷新、删除确认与结果核对。首页“管理作品”进入，游客登录成功后回跳；离开后重进读取首批，不缓存跨路由列表。
- 真实接口：`GET /api/articles/feed`、`GET /api/users/me`、`GET /api/auth/csrf`、`POST /api/auth/login`、`GET /api/users/me/articles`、`DELETE /api/articles/{id}`及结果核对使用的`GET /api/articles/{id}/edit`。数据类型直接对应后端 DTO，ID 始终使用字符串。
- 编辑接口：`GET /api/articles/{id}/edit`、`POST /api/articles`、`GET /api/tags?q=…&limit=20`、`POST /api/media/uploads`；所有写操作携带当前会话 CSRF，不自动重发文章或文件上传。
- `/articles/new`、`/articles/:id/edit`：完整 Tiptap 正文、封面与正文图片上传、标签搜索、发布保存弹窗、离开确认和登录失效后的临时恢复。保存成功留在编辑页，新建转为同 ID 编辑。
- 搜索、热门、关注、文章详情、视频、合集、点赞写入、评论和个人中心保留外观与未开放提示；不增加注册、找回密码、记住登录和退出入口。
- 作者使用默认头像，评论数显示“—”；浏览、点赞数量及本人点赞状态使用真实接口数据。

推荐流每次固定读取20项，以 `nextCursor=null` 判断结束；空页不等于结束。连续三页没有新文章时暂停自动请求，允许手动继续。失败保留内容，限流遵守 `Retry-After`；过期或无效游标需点击重新加载，重新从首屏开始。列表暂不虚拟化，持续浏览会增加 DOM 数量。

登录态来自用户资料接口；401 判定游客，503 或网络失败保留未知态。Session ID 仅通过 HttpOnly Cookie 传递，CSRF 只留内存。编辑表单仅在会话失效跳转登录前写入当前标签页的 sessionStorage；同账号、同文章、两小时内恢复一次即清除，不是自动保存。认证成功后的读取异常不会重发登录。用户名去首尾空白并保留大小写，密码原样发送。

已有确认身份时，后台资料复核静默进行，不增加提示条或挤动列表；非401失败保留资料和列表的内部状态，内容区统一展示设计稿“内容加载失败／请检查网络连接后重试／重新加载”。身份恢复后显示原列表并保持位置。业务接口401会同时作废在途资料读取；账号变化重新建立本人列表。登录回跳仅接受管理页、新建文章页和合法的文章编辑地址，其余目标回首页。

管理列表每次20条，距离底部200px续页，以`nextCursor=null`结束；空页仍可续读，连续三页无新增则暂停自动读取，同游标重复则重开查询。首次显示五条骨架，追加失败只显示原稿一行“加载失败，点击重试”；刷新期间保留旧条目，成功替换并只让列表回顶，失败保留内部数据和位置、展示同一加载失败态并停用旧游标。游标无效、过期和429保留必要的重试及冷却逻辑，不另设技术状态说明。列表无观察器时支持手动加载，不定时轮询，也不虚拟化。

管理页不展示精确总数；阅读及点赞为真实值，评论和收藏显示“—”。删除先取得CSRF，204后才移除；前置凭证失败不发送DELETE。写入结果未知时不自动重发，用户主动通过作者接口核对；隐藏409或不存在404时移除，200保留并允许重新确认。已确认移除的ID在本页内排除，防止短暂旧卡片和迟到响应重新展示。该排除状态离开页面即清理。

## 文章编辑页与开发上传（2026-11-12）

设计来源为 `Community / community / 240:2763`，指纹 `374ed908e3c1a264`。新增完整正文工具栏，外层沿用原稿；成功后留在编辑页，标签改用现有关键词搜索，提交统一显示处理中、成功和失败弹窗。读取权限、已删除等页面状态保持独立。编辑器按路由懒加载，主页不下载 Tiptap 主体。

开发配置步骤：

1. 将 `fronted/.env.development.example` 复制为 `.env.development.local`，填写本机 MinIO 的真实端口和桶。
2. 将后端实际开发环境文件中的 `MEDIA_STORAGE_UPLOAD_ENDPOINT` 改为 `http://127.0.0.1:5173/__media/upload`，然后重启后端。此处仅改上传入口，存储端点、公开读取地址和 Webhook 保持原配置。
3. 重启 Vite。浏览器继续原样使用授权中的 `upload.url`，上传代理只对固定桶 POST 转换 JSON，不转发社区凭证，不等待 READY。

文章上传、保存及公共上传函数没有固定延迟或就绪轮询。未来头像功能才在开发环境上传后、立即绑定前增加 500ms 等待；当前不实现头像。图片暂时不可读可手动重新加载封面预览，媒体尚未就绪时保存失败保留输入。新建响应丢失后手动重发仍可能重复创建，不提供幂等或结果核对。

真实联调可在前端目录显式运行 `node scripts/verify-article-editor-live.mjs`。它读取本机 `backend/.env` 的管理员初始化凭证，也允许通过 `EDITOR_LIVE_ADMIN_USERNAME/PASSWORD` 覆盖；凭证仅在内存中使用。脚本创建专用临时作者、使用 5177 端口启动 Vite，验证格式往返、真实图片上传与绑定，最后解绑图片、隐藏文章并逻辑删除临时作者。运行前确保后端、存储及 Webhook 已就绪，不与其他 5177 服务并用。

新增清除格式、Unicode 码点正文计数、代码语言选择、语法高亮及代码块 Tab/Shift+Tab 缩进。自动识别只影响显示；未列出的已有语言标识保留并按纯文本显示。清除格式保留文字和图片，可一次撤销。高亮、计数和浮层状态不写入正文协议，也不触发未保存提醒。正文编辑器及其高亮依赖按需加载。
