# 用户资料、个人简介与共享缓存

本期仅提供后端能力，不修改前端。文字资料通过统一入口编辑，目前只开放简介`bio`；头像继续使用独立接口。性别、生日暂未增加，后续增加时需分别定义校验及公开范围。

## 接口

所有接口要求有效Session，修改接口还需CSRF。ID在JSON中始终为字符串。

| 接口 | 请求与响应 |
| --- | --- |
| GET `/api/users/me` | 返回`userId、username、role、avatarMediaId、avatarUrl、bio` |
| GET `/api/users/{userId}` | 数字正BIGINT路径，返回`userId、username、bio、avatarMediaId、avatarUrl`，不返回角色和认证信息 |
| PATCH `/api/users/edit` | `Content-Type: application/json`，本期仅接受`{"bio":"个人简介"}`，返回更新后的本人资料 |
| PUT `/api/users/me/avatar` | `{"mediaId":"标准UUID"}`，保持现有媒体归属、用途和READY校验，返回本人资料，包括bio |
| DELETE `/api/users/me/avatar` | 清空头像，204 |

指定用户资料允许查询禁用及软删除账号，只有物理不存在才返回`404 USER_NOT_FOUND`。这不授予目标用户使用能力：本人请求仍经过现有账号状态、认证版本和Session有效期校验，停用或软删除账号不能登录、编辑或发布，原会话失效返回401。

## 简介与部分更新

简介为单行纯文本，拒绝换行及控制字符，再去除首尾空白，最多50个Unicode码点；普通中文、英文、标点各占一个码点，组合emoji可能占多个码点。超限及非法内容返回`400 INVALID_BIO`，不按UTF-16长度截断输入。

数据库为`bio VARCHAR(50) NOT NULL DEFAULT ''`，旧用户及未填写用户均返回空字符串。请求未提供bio表示不修改；`null`、`""`及规范化后的空字符串均清空。本期仅开放bio，所以`{}`没有可编辑字段，返回400。

仅接受明确的字段白名单，数值、布尔、数组、对象不会强制转成字符串；未知字段（包括`userId、username、role、status、avatarMediaId`）、重复JSON键、多个JSON值及空请求返回400。结构错误使用`INVALID_USER_EDIT`，框架级请求错误使用`INVALID_REQUEST`。

前端只提交变化字段；后端仍在事务内锁定用户并校验状态和认证版本，与当前值比较后局部更新。规范化后相同的简介成功返回，不写库、不失效缓存。请求身份只来自Session，不接收客户端指定的目标用户。简介变更不修改authVersion或Session，也不调用头像媒体引用流程。

不强制并发请求顺序，不提供资料版本或409冲突检测；同字段以数据库最终提交结果为准。未来新增字段时仅更新本次提供且变化的字段，避免覆盖其他字段。

## 缓存与账号删除

`/me`、指定用户资料和文章作者共享用户展示投影：`userId、username、avatarMediaId、bio`。本人角色来自已验证的Session，缓存不含密码、角色、状态和认证版本，也不保存生成后的媒体URL。命中时不再查询资料表，但认证链路的主库状态校验保留。

缓存未命中复用现有用户操作锁与回源名额，锁内二次检查后通过主库短事务读取，事务结束后验证token并回填。停用和软删除目标不额外查询状态。确认不存在才缓存负值，Redis或SQL故障、锁竞争超时返回503，不能转换成404。

简介实际变化、头像设置或清空、软删除均在最外层事务提交后失效同一用户缓存；回滚不失效。创建继续清理可能存在的负缓存，不删除文章缓存或更新ES。

编辑与头像设置响应直接返回事务中的最新资料。缓存采用有限重试失效及固定TTL，后续读取允许短暂返回旧资料，不承诺立即读取一致性。

账号软删除会撤销登录及发布等使用能力，保留用户资料和历史内容供展示，同时删除该账号的头像关联并清空头像字段。缓存更新后，资料接口的`avatarMediaId`、`avatarUrl`返回null，文章作者的`authorAvatarUrl`同样为空，由前端展示默认头像。原头像文件按既有无引用媒体回收机制清理，不在删除账号事务中同步删除存储对象。前端现有Avatar组件已支持空地址回退，本次不增加前端代码或由后端返回默认头像URL。

## 发布与验证

先执行新增V10迁移，再启用`USER_BASIC_CACHE_VERSION=v2`（新默认值）或全新兼容版本。不得继续显式配置v1，也不得与使用旧命名空间的实例同时接流量；用户缓存直接冷启动。文章缓存版本不变，不需重新构建文章或ES。回滚保留新增列并使用全新旧格式用户命名空间，避免复用陈旧投影。

缓存协议、指标、TTL及隔离测试命令见[公开读取缓存说明](../../../../../backend/docs/public-read-cache.md)。普通单元测试执行`mvn test`；真实HTTP/MySQL/Redis测试通过仓库的`infra/test/run-search-tests.ps1`运行，包含`UserProfileHttpIntegrationTests`及既有头像、文章、认证回归测试。
