# 点赞分区聚合实施与验证记录

日期：2026-11-17。实现采用固定分区、批内文章聚合及文章级独立事务，数据库表结构和消息正文保持兼容。

## 实施结果

- 默认4分区，每队列Quorum与Single Active Consumer；每实例注册4个串行监听容器，备用由Broker接管。
- 路由统一为floorMod(Long.hashCode(articleId), partitionCount)，普通发布和死信重放使用相同规则。
- 每批最多20条，100ms收集等待，prefetch20；按文章分组后按关系保留最高版本。
- 每文章组一个READ COMMITTED事务，关系按userId升序锁定和裁决，最多更新一次计数。零净增量也推进版本并检查计数基线。
- 组提交后维护状态缓存、最多失效一次文章计数缓存，逐条确认全部合法原消息；失败组隔离，Channel异常终止回调并保留剩余消息重投。
- 保留原有重试、SQL耗时及缓存失败指标，新增有限分区维度的批大小、组大小、合并数量、组耗时与结果指标。

## 验证

执行入口：`./infra/test/run-like-tests.ps1 -Light`。11个测试类共33个用例通过，无失败、错误或跳过。其中MySQL真实事务5例，RabbitMQ窄范围集成2例。随后消费端指标兼容修改单独重跑6个消费者用例通过。

- 单测覆盖最高版本合并、冲突关系隔离、固定路由与拓扑参数、配置边界、发布确认、交错投递标签、文章组失败独立性、未知提交重试、缓存单条失败继续及中断后的未确认保留。
- MySQL验证多关系净增量正/负/零、墓碑与版本幂等、缺计数行整组回滚和并发关系/热点计数一致性。
- RabbitMQ验证原生混合批次、低流量部分批次、每队列单活以及关闭活跃连接后的备用接管和未确认重投。
- `mvn -q -DskipTests package`通过，包含全量测试代码编译；PowerShell脚本语法检查和Git差异空白检查通过。
- 没有运行浏览器交互、完整Web双实例重启、容器重启故障演练或容量压测，不能据此宣称吞吐提升倍数。

单活测试使用实际投递与接管作为判据，不把Quorum队列AMQP消费者计数解释成活跃与备用消费者总数。

## 适用边界

分区不能拆散单篇热点文章，同分区慢组退避仍会延迟后续文章。队列容量为每队列预算，默认4个分区和共享死信合计320MiB配置正文预算，不含在途投递及Broker额外开销。分区数或哈希算法修改须停实例切换，禁止新旧规则混跑。
