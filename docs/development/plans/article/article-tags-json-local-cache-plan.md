# 文章标签 JSON 存储与本地目录搜索实施计划

> 2026-11-12｜本期后端实现已落地；本机开发库已升级V9并完成v4缓存墓碑重建，结果见[专项验收](../../reports/article/article-tags-validation-2026-11-12.md)。旧关系表物理删除属于后续发布。
>
> 依据[分享对话最新一轮](https://chatgpt.com/share/6af48ae2-c740-83ee-b9bf-d94214d27368)及用户后续确认修订。当前契约见[公开标签接入说明](../../../public/guides/article/zh-CN/article-tags.md)。本版取代“Redis共享目录”和“每次保存固定批量存在性SQL”的旧提案。

## 1. 固定范围

- 只修改后端、数据库迁移、测试与相关文档，不修改前端。
- 标签仅管理员新增，无改名、禁用、删除和合并；名称保存与判重规则不变。
- 文章允许0～5个标签，原始输入先限制数量，再去重按数值排序，保存时整体覆盖。
- 文章标签引用以article.tag_ids JSON保存，不再读取或写入独立关系行。
- MySQL保存事实，ES负责文章标签筛选；标签选择器只搜索JVM本地目录。
- 不增加Redis标签目录、持久化本地缓存、Caffeine、专用标签索引或通知队列。

## 2. 存储与目录快照

V8新增单行目录版本表，版本从1开始。TagRepository所有插入与目录增版共享事务，重名或回滚不增版；所有维护写入也必须遵循该协议，不用MAX(id)或时间戳替代。

V9新增tag_ids JSON，覆盖隐藏文章回填，空集合为[]。窗口聚合固定数值顺序，CHECK限制数组和五项上限；历史超限中断迁移。Java使用不可变List<Long>，HTTP保持字符串ID，ES保持现有字符串数组。

内存包含TagView、预计算搜索字段的SearchableTag、带版本和ID映射的TagSnapshot。完整目录和版本在独立只读RR事务中读取，事务返回后构建不可变快照，AtomicReference只接受更高版本。不对局部增量打补丁后标记完整新版本。

## 3. 搜索与按版本校验

GET /api/tags保持登录要求，新增q和limit：空q返回[]，limit默认10、范围1～20。关键词原始上限128码点，NFKC、strip及Locale.ROOT小写后最多32码点。前缀优先，再补包含匹配；同级按搜索字段及数值ID排序。普通搜索零SQL，不建立关键词结果缓存。

文章保存事务之前，对整个目标集合一次校验：

1. 空集合、本地全部命中直接通过，不查询SQL。
2. 本地缺ID才独立查询主库版本；低于操作开始的快照版本返回503。
3. 查询后重读本地引用；其他线程已补齐则通过，本地已达到SQL版本则直接判断。
4. 仅本地落后时同步一次完整目录，达到已观察版本后再次比较整个集合，不循环追赶。
5. 仍缺ID返回400 INVALID_ARTICLE；SQL、刷新或等待失败返回503 DEPENDENCY_UNAVAILABLE。

不再调用COUNT/IN存在性查询。标签不会失效，因此校验通过后无需在文章事务中重查或锁标签。文章准备结果进入提交服务前必须经过统一校验。

## 4. 刷新和异常

Web启动尝试初始化，失败不影响其他模块，目录未初始化返回503而非空结果。定时默认60秒fixed-delay，初次检查随机错峰0～60秒；版本变化才完整加载。管理员提交成功后尽力刷新本实例，失败不覆盖新增成功结果；其他实例依靠定时校验收敛。

所有全量刷新共用实例内锁，等待其他刷新最多300ms，目录SQL每语句超时2秒，加载失败后冷却1秒。已有快照继续提供搜索和本地命中校验，缺ID操作遇到依赖失败不误判非法。非Web维护命令不加载和调度目录。

文章中的可信ID若尚未加载，名称装配复用上述版本检查；最新完整目录仍缺ID属于数据错误，告警并返回503，不丢标签、不写文章不存在的负缓存。

## 5. 文章和ES改造

标签JSON、正文、媒体引用、元数据版本及Outbox沿用现有事务原子性。移除关系DELETE/INSERT，权限、隐藏状态、媒体锁顺序和提交结果判定不变。

文章详情、列表、编辑直接读行内ID，列表不读正文。文章Redis投影只含tagIds，名称、作者和URL在事务与文章缓存锁释放后组装；响应仍含tags: [{tagId,name}]，一页批量使用同一目录快照。

索引元数据一次批量查询携带JSON，删除关系查询。ES mapping和可靠同步协议不变，重建不依赖目录。标签候选用当前文章投影再次核对，不增加SQL，新增发现仍受异步索引延迟影响。

## 6. 迁移与发布

采用维护窗口停止旧实例和写流量，不实现在线双写，不修改历史V3。备份后执行V8/V9，核对标签集合、有效ID、去重与数量，异常不截断。

文章缓存升级v4；显式环境覆盖也必须选未使用的新版本，按既有非Web恢复流程重建隐藏墓碑和完成标记后再启新实例。旧表首轮保留但停止读写，验证后才安排单独迁移删除，本次不交付自动删表迁移。

开放新写流量后旧关系已可能陈旧，不能直接回滚旧应用；必须从当前JSON恢复关系，并使用新的兼容缓存命名空间重建墓碑。
