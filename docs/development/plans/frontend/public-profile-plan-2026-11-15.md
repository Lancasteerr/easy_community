# 个人主页前端实施审查稿

日期：2026-11-15。状态：方案已获使用者认可并实施，结果见[个人主页验收记录](../../reports/frontend/public-profile-validation-2026-11-15.md)。以下保留审查时的设计与取舍背景。

## 一、后端核对与本期取舍

本期建议只改前端，不新增后端接口、数据库字段或关注模型。本人主页和访客主页都展示公开资料及公开文章，使用同一条公开读取链路；本人身份只决定是否出现“编辑资料”。

| 能力 | 当前代码与接口 | 本期接入方式 |
| --- | --- | --- |
| 用户公开资料 | `GET /api/users/{userId}`，游客可读，包含 `userId、username、avatarMediaId、avatarUrl、bio、createdAt` | 用户名、头像、简介、ID、加入时间使用真实数据 |
| 本人身份 | `GET /api/auth/session`，全局仅保存 `userId、role` | 已确认的会话 ID 与路由 ID 相同才显示本人操作；公开读取不等待会话初始化 |
| 作者公开文章 | `GET /api/articles/search?authorId={userId}&sort=latest&size=20&cursor=…` | 本人和访客统一使用，固定按最新发布排序，不混用本人管理接口的游标 |
| 文章卡片 | 返回标题、摘要、封面、发布时间、浏览量、点赞量与 `likedByMe` | 使用真实数据，不用设计稿的示例文章填充真实列表 |
| 简介、头像编辑 | 已有 `/settings/profile` 及资料、媒体写接口 | 从本人主页进入现有设置页，不在主页新增编辑表单或上传入口 |
| 文章总数 | 列表响应只有 `items、nextCursor`，没有精确总数 | 按使用者要求展示样例值；不把已加载条数当成总数，不遍历所有分页计数 |
| 关注、粉丝 | 未发现关系接口及对应存储模型 | 数量展示样例，关注按钮只提示未开放 |
| 个人封面 | 用户资料没有封面字段及编辑接口 | 使用 Figma 中的统一静态封面，不提供更换入口 |
| 评论、收藏等 | 本轮没有相应可接入能力 | 评论延续现有卡片的“—”和未开放提示；不增加收藏、版区、标签或总获赞模块 |

后端核对依据：

- [UserMetadataController.java](../../../../backend/src/main/java/com/febrie/backend/user/web/UserMetadataController.java)、[UserProfileQueryService.java](../../../../backend/src/main/java/com/febrie/backend/user/application/UserProfileQueryService.java)、[UserMetadataView.java](../../../../backend/src/main/java/com/febrie/backend/user/application/dto/UserMetadataView.java)。
- [SecurityConfiguration.java](../../../../backend/src/main/java/com/febrie/backend/auth/infrastructure/config/SecurityConfiguration.java) 明确允许游客读取数字用户 ID；`/me` 仍要求登录。
- [ArticleSearchController.java](../../../../backend/src/main/java/com/febrie/backend/article/search/web/ArticleSearchController.java)、[ArticleSearchService.java](../../../../backend/src/main/java/com/febrie/backend/article/search/application/ArticleSearchService.java)：支持作者筛选，服务端重新核对当前文章投影的作者并过滤不可公开项。
- 已阅读现有资料和作者搜索集成测试，确认其覆盖游客读取、加入时间、筛选、游标隔离和点赞字段；本轮没有重新运行这些测试。

本机后端 `127.0.0.1:8080` 的匿名读取探测结果：

| 请求 | 结果 |
| --- | --- |
| `/api/articles/feed?size=1` | 200，返回一条文章及 `nextCursor` 字段 |
| `/api/users/1` | 200，包含全部六个公开资料字段 |
| `/api/articles/search?authorId=1&sort=latest&size=1` | 200，返回一条文章及 `nextCursor` 字段 |

以上仅验证当前实例的公开读取可用性，不代表登录后点赞、完整续页或全部异常已经联调通过。旧用户资料指南中“所有接口要求有效 Session”的描述与现实现不一致，后续交付时一并修正文档；旧验收中的 ES 故障保留为历史记录。

## 二、设计依据与需要修正的表达

Figma：`Community / community`，通过 `figma-local-agent` 读取。

| 节点 | 用途 |
| --- | --- |
| `84:1052` | 个人主页交付范围 |
| `84:1053`、`84:1147` | 本人态、访客态主稿，均为 1440 × 1024 |
| `84:1068`、`84:1162` | 完整资料头部 |
| `87:1878`、`87:1962` | 发布文章列表，有封面与无封面变体 |
| `87:1836`、`87:1854` | 个人信息卡片 |
| `84:1254`、`84:1260` | 本人、访客空状态 |
| `84:1266` | 设计约束：只展示发布文章、不含版区收藏、无总获赞、无标签、卡片不重复作者、缺失资料为“—” |

滚动参考：[使用者指定的森空岛主页](https://www.skland.com/profile?id=2725309880901)。已通过浏览器实际观察初始态、向下滚动后的简要资料卡和回到顶部后的展开态。只参考它的滚动行为，页面颜色、尺寸和模块范围仍以本项目 Figma 为准。

需要明确的设计取舍：

1. 原稿的统计在头部、列表“发布”旁和信息卡中重复出现，访客稿也存在数值不一致。建议统一样例配置为文章 `12`、关注 `19`、粉丝 `1.2k`；所有文章总数位置都引用同一个 `12`，均无点击、悬浮提示或导航行为。实际列表可以为空，与样例统计独立。
2. 文章封面节点名为“16:9”，实测尺寸却是 `788 × 356`。建议按节点实际尺寸还原该页比例，首页现有的 16:9 保持原行为。
3. 信息卡的描述与头部简介建议使用同一份真实 `bio`，避免引入另一份无法编辑的虚构资料。缺失简介显示“—”，空头像或坏头像使用现有默认头像。
4. 原稿没有简要资料卡及触发状态。这部分属于本轮补充设计，应在实施后单独展示给使用者验收，不能宣称完全来自原稿。

## 三、已确认的交互边界

| 场景 | 已确认行为 |
| --- | --- |
| 首页文章作者头像、名字；阅读页作者入口 | 当前标签页进入 `/users/:userId` |
| 顶栏头像菜单“个人主页” | 新标签页打开本人 `/users/:userId`，与内容管理、设置入口保持一致 |
| 本人“编辑资料” | 新标签页打开现有 `/settings/profile` |
| 访客“+ 关注” | 保留按钮，点击提示“功能暂未开放”；不改变关注状态，不跳转登录 |
| 文章、关注、粉丝统计 | 展示样例数据，点击无反应 |
| 页面滚动 | 最终采用森空岛式整页统一滚动；完整资料卡滚出后，简要资料卡在顶栏下吸顶 |

最后一项已替代此前选择的“文章列表独立滚动”。不再采用固定完整资料头部或最低 900px 画布方案，避免矮窗口只剩很小的文章区域。

## 四、其余交互建议，供整体审查

### 资料卡展开与收起

- 首屏按 Figma 展示完整卡片：统一封面、96px 头像、用户名、简介、三项统计及本人／访客操作。
- 完整卡片底边越过顶栏下方的吸附边界时，显示约 88px 高的简要卡片；它保留约 48px 头像、用户名、三项统计和同一个操作按钮，隐藏封面与简介。
- 简要卡片的按钮与完整卡片行为完全一致；隐藏态不占键盘焦点，避免两个重复可操作入口。
- 回滚至完整卡片重新进入展示边界时，恢复完整态。用稳定占位和遮挡高度处理防止文章跳动，不因状态切换重建文章列表或重新请求数据。
- 顶栏和简要卡片共用明确的层级及遮挡背景；右侧个人信息卡随内容自然滚走。先不增加“回到顶部”按钮、资料卡展开按钮或复杂动画。
- 延续项目 1440px 最小桌面画布与 1227px 内容宽度，窄屏横向滚动；文章区宽 840px，信息卡宽 370px，间距 17px。矮屏通过同一个整页滚动口访问内容，不设文章内部滚动口。

### 文章与分页

- 标题和封面进入现有 `/articles/:id`，当前标签页打开；卡片空白区域不整体变成链接，避免干扰点赞和文本选择。
- 卡片不重复显示作者及关注按钮，保留发布时间、阅读数、标题、摘要、可选封面、真实点赞和未开放评论。
- “发布”是唯一的当前分区，不切换；“最新发布”只表示固定排序，不做下拉菜单。
- 每页 20 条，距滚动区底部约 600px 自动续页；仅以 `nextCursor=null` 判断结束，空页不直接等于空列表。
- 复用现有分页规则：请求互斥、按文章 ID 去重、连续三页没有新增时暂停自动读取并显示手动继续；重复游标要求重新加载，429 遵守 `Retry-After`。
- 首次加载显示骨架；确认为最终空列表后，本人显示“还没有发布文章”和“去发布”，访客显示“该用户还没有发布任何文章”。本人“去发布”进入现有 `/articles/new`。
- 首次失败在列表区域显示重试；追加失败保留已有文章，在底部提示“加载失败，点击重试”；无效或过期游标由用户主动重新加载首批。已成功读取的资料不因文章加载失败消失。
- 暂不增加常驻刷新按钮，浏览器刷新重新读取；不轮询、不预读所有分页、不做列表虚拟化。

### 身份、资料异常与跨页返回

- 路由 ID 按正 BIGINT 范围验证，全程使用字符串。非法 ID 不发请求；用户资料 404 显示“用户不存在”及返回首页，不能误判为空文章列表。
- 资料请求失败与用户不存在分开处理；网络或 503 显示普通加载失败和重新加载，不用虚构资料补齐页面。用户资料成功后才开始该作者列表查询。
- 公开主页不强制登录。本人按钮仅根据已确认会话显示；会话尚未确认或复核失败时暂停本人操作及点赞，仍可阅读公开内容。
- 复用现有点赞组件：游客点击进入登录，并将安全回跳白名单扩展到 `/users/:userId`；登录完成返回该主页，不自动补发之前的点赞。
- 当前文档内，文章阅读后后退恢复已加载列表与位置；快照以作者 ID 和历史项区分。整页刷新、身份变更及登录边界继续沿用现有清理机制，不新增持久缓存。
- 公开主页登出、会话失效或确认换号时原地址整页刷新，不沿用旧账号的 `likedByMe`。个人主页不能加入受保护路由名单。
- 设置页保存仍按现有行为刷新设置标签页。建议本轮原主页使用手动刷新读取新头像、简介，不增加跨标签广播或后台资料同步；这一点需要随整体方案审查。
- 加入时间将 `createdAt` 按浏览器本地时区展示为 `YYYY-MM-DD`，缺失或不可解析时显示“—”；ID 只读，不新增复制按钮。

## 六、分批实施与验收

审查通过后默认在本地 `master` 实施，保持小批次；以下是建议提交边界，本轮尚未创建提交。

1. `feat(profile): 接入公开资料与作者文章查询`：补齐作者查询、路由 ID 校验、资料与游标状态及必要行为测试。
2. `feat(profile): 实现个人主页与简要资料吸顶`：还原本人／访客主稿，补充简要卡片、文章展示场景和静态资源，验证高度切换与错误状态。
3. `feat(profile): 打通作者入口与登录回跳`：接通菜单、首页、阅读页、设置入口、登录返回和阅读位置恢复，更新页面范围及接口文档。

每批代码添加适当中文注释，重点解释身份前提、游标规则、吸顶边界和取消逻辑；不为内部已保证的前提重复校验，不把全部逻辑堆入页面文件。

验收重点：

- 类型检查、生产构建和相关现有单元测试；新增测试聚焦作者切换迟到响应、资料 404／503、分页互斥／去重／游标及安全回跳，不为纯样式或静态样例写镜像测试。
- 浏览器检查 1440 × 1024 完整态与简要态、1440 × 768 矮屏、1920宽屏及窄屏横滚；同时检查右侧信息卡滚动、顶栏菜单与简要卡片层级。
- 检查吸顶切换前后文章不跳动、按钮不重复聚焦、返回主页的锚点不被遮挡；短列表及空列表不强行生成滚动距离。
- 检查本人／其他登录用户／游客、空简介、空头像、坏封面、长用户名、有／无封面和最终空列表。
- 核对所有样例统计完全一致且点击无反应；关注、评论仅提示未开放；文章和点赞仍使用真实数据。
- 真实后端验证公开资料及作者列表；需要登录的点赞、设置新标签页、会话失效和回跳作为明确验收项，不以当前三次匿名探测代替完成证据。

整体审查重点：简要卡片保留字段与约 88px 高度、同一简介在两处展示、设置后原标签页手动刷新、文章封面采用 788:356 实测比例，以及是否接受本轮不设置常驻列表刷新按钮。
